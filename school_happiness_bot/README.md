# Бот школы «Счастья»

Telegram-бот на [aiogram 3](https://docs.aiogram.dev/), который приветствует
пользователя фразой «Здравствуйте! Я ищу людей, которые счастливы, — чтобы
вместе построить школу «Счастья»», ведёт с ним диалог и собирает контакты
(имя, город, чем готов помочь, телефон), сохраняя их в базу SQLite.

## Диалог бота

1. `/start` — приветствие и вопрос об имени. Можно ответить как просто
   именем, так и целой фразой («Меня зовут Владимир») — бот распознаёт имя
   внутри фразы (см. «Классификация через ИИ» ниже).
2. Город.
3. Выбор способа помощи: кнопки (обучение, организация, волонтёрство,
   финансовая поддержка, другое) **или** свободный текст своими словами —
   в этом случае ИИ относит ответ к одной из тех же категорий.
4. Телефон — кнопкой «Отправить номер телефона» или вручную.
5. Подтверждение введённых данных.
6. Сохранение контакта в `contacts.db` и (опционально) уведомление
   администратора в Telegram.

`/cancel` в любой момент прерывает диалог.

`/export` — только для администратора (тот, чей `chat_id` указан в
`ADMIN_CHAT_ID`): бот присылает файл `school_happiness_contacts.xlsx` со
всеми собранными контактами. Если ID не совпадает или `ADMIN_CHAT_ID` не
задан, бот теперь так и напишет — молчать в ответ он больше не должен.

`/whoami` — доступна всем, бот отвечает вашим настоящим Telegram ID. Нужна,
чтобы свериться со значением `ADMIN_CHAT_ID`, если `/export` не срабатывает.

## Классификация через ИИ

Модуль `ai.py` использует OpenRouter (по умолчанию `openai/gpt-4o-mini`,
temperature 0.2) для двух задач:

- **Категория помощи** — если посетитель не нажал кнопку, а написал текст
  своими словами («хочу помочь финансово», «готов быть волонтёром»), ИИ
  относит ответ к одной из уже захардкоженных категорий из `HELP_TYPES`
  (`keyboards.py`). Список категорий не меняется и не расширяется — ИИ
  только выбирает из него ключ; при любой неуверенности или ошибке
  запроса возвращается категория «Другое».
- **Разбор имени** — если человек отвечает не именем, а фразой («Меня
  зовут Владимир», в том числе с опечатками), ИИ вытаскивает из неё само
  имя, а не сохраняет фразу целиком.

Обе функции работают только при заданном `OPENROUTER_API_KEY`. Без него
бот не падает и не блокируется — категория помощи по-прежнему выбирается
кнопками (свободный текст в этом случае просто уйдёт в категорию
«Другое»), а для имени срабатывает лёгкий запасной разбор по шаблону
«меня зовут …» (без ИИ он не так устойчив к опечаткам, но не оставляет
пользователя без ответа).

Настройка — в `.env`:

```
OPENROUTER_API_KEY=sk-or-...
OPENROUTER_MODEL=openai/gpt-4o-mini   # необязательно, это значение по умолчанию
```

Ключ можно получить на [openrouter.ai/keys](https://openrouter.ai/keys).

## Установка

```bash
cd school_happiness_bot
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

1. Получите токен бота у [@BotFather](https://t.me/BotFather).
2. Скопируйте `.env.example` в `.env` и заполните:

```bash
cp .env.example .env
```

```
BOT_TOKEN=123456:ваш_токен
ADMIN_CHAT_ID=123456789   # необязательно: ваш chat_id для уведомлений
```

Узнать свой `chat_id` можно, например, у бота [@userinfobot](https://t.me/userinfobot)
(обязательно в личном чате с ним, не в группе — ID группы/канала выглядит
иначе и не подойдёт) либо командой `/whoami` у самого бота школы «Счастья».

## Запуск

```bash
python bot.py
```

Бот сохраняет собранные контакты в файл `contacts.db` (SQLite) в таблице
`contacts`. Просмотреть их можно, например, так:

```bash
sqlite3 contacts.db "SELECT * FROM contacts;"
```

Либо проще: отправить боту команду `/export` (с аккаунта, чей `chat_id`
указан в `ADMIN_CHAT_ID`) — он пришлёт Excel-файл со всеми контактами прямо
в чат, без доступа к серверу.

## Деплой на Railway

Код бота лежит в подпапке `school_happiness_bot/`, а не в корне репозитория.
В сервисе на Railway задан **Root Directory = `school_happiness_bot`** —
рабочая директория контейнера указывает прямо на эту подпапку, поэтому
команда запуска — **`python bot.py`**, без префикса `school_happiness_bot/`.

Эта команда прописана сразу в двух местах — в `railway.json`/`Procfile`
в корне репозитория и в `railway.json`/`Procfile` внутри самой
`school_happiness_bot/` — чтобы не зависеть от того, откуда именно Railway
подхватывает конфиг при заданном Root Directory. Если Root Directory
когда-нибудь сбросят на пустой (сборка из корня репозитория), обе команды
нужно будет вернуть к `python school_happiness_bot/bot.py`.

⚠️ **Если Start Command вписан вручную в настройках сервиса**
(Settings → Deploy → Start Command в панели Railway), это значение
перекрывает `railway.json`/`Procfile` из репозитория и не обновится само
по себе. Проверьте это поле: там должно быть `python bot.py`, либо поле
стоит вовсе очистить, чтобы Railway брало команду из `railway.json`.

Что нужно сделать:

1. Создать сервис в Railway и подключить этот репозиторий.
2. В настройках сервиса добавить переменные окружения `BOT_TOKEN` (и, при
   необходимости, `ADMIN_CHAT_ID`) — так же, как в `.env`.
3. Задать Root Directory = `school_happiness_bot` и убедиться, что Start
   Command не переопределён вручную (см. предупреждение выше).
4. Задеплоить. Railway поставит зависимости из `requirements.txt` и
   запустит бота как процесс `worker` — он работает через polling,
   отдельный веб-порт ему не нужен.

### Volume для базы данных

Без Volume файл `contacts.db` живёт в эфемерной файловой системе контейнера
и теряется при каждом редеплое. Чтобы контакты сохранялись:

1. В сервисе на Railway откройте вкладку **Volumes** → **New Volume**.
2. В качестве **Mount Path** укажите `/data`.
3. Добавьте переменную окружения `DB_PATH=/data/contacts.db` (бот читает
   путь к базе из этой переменной, см. `database.py`; если её не задать,
   используется относительный `contacts.db`, который на Volume не попадёт).
4. Передеплойте сервис — с этого момента `contacts.db` будет храниться на
   Volume и переживёт редеплой.

## Структура проекта

```
school_happiness_bot/
├── bot.py           # точка входа, запуск polling
├── ai.py             # классификация категории и разбор имени через OpenRouter
├── config.py        # чтение настроек из .env
├── database.py       # работа с SQLite
├── handlers.py       # логика диалога (FSM)
├── keyboards.py       # inline/reply-клавиатуры
├── states.py         # состояния диалога
├── requirements.txt
├── .env.example
└── README.md
```
